But in your LDAP tree, groups are groupOfNames, not posixGroup. There’s a mismatch:

Your groups are DN-based (groupOfNames with member attributes).
The template you used for the user expects POSIX attributes (uidNumber, gidNumber).
Result: The user ends up with POSIX-style attributes, but pfSense is looking for DN-style membership.

That’s why pfSense isn’t showing groups: the testuser you created is missing the right structural object class and/or DN membership attributes.

Fix options
Option 1: Create DN-style users (simplest for pfSense)

When you create a user in phpLDAPadmin:

Choose the “Generic: User Account” or “inetOrgPerson” template (instead of posixAccount).
Required attributes are then just cn, sn, uid, userPassword.
No gidNumber or uidNumber needed.
After saving, add the user’s DN (uid=...,ou=people,...) to the group’s member attribute (cn=VPN-Users,...).

This matches your existing groups (groupOfNames). pfSense will then see group membership correctly.

Option 2: Stick to POSIX (RFC2307) everywhere

If you want to use posixAccount/posixGroup:

Keep uidNumber and gidNumber on users.
Switch groups to posixGroup and use memberUid.
In pfSense, enable RFC 2307 Groups and set Group member attribute = memberUid, Group object class = posixGroup.
